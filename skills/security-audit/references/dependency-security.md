# Dependency & Supply Chain Security Reference

## Python Dependency Scanning

```bash
# pip-audit — official PyPA tool (recommended)
pip install pip-audit
pip-audit                           # scan current environment
pip-audit -r requirements.txt      # scan from requirements file
pip-audit --fix                    # auto-fix where possible

# safety — OSV database
pip install safety
safety check
safety check -r requirements.txt --json

# Semgrep — includes dependency checks
pip install semgrep
semgrep --config=p/python-security .

# In CI (GitHub Actions)
# - name: Audit dependencies
#   run: pip-audit -r requirements.txt --strict
```

## Python Dependency Pinning

```
# ❌ requirements.txt with loose pins — unpredictable builds
requests
fastapi>=0.100
pydantic~=2.0

# ✅ Fully pinned requirements.txt — reproducible and auditable
fastapi==0.115.6
pydantic==2.10.4
requests==2.32.3
uvicorn==0.34.0

# ✅ Use pip-compile to generate pinned from abstract requirements
# requirements.in (abstract — what you specify)
fastapi>=0.100
pydantic>=2

# requirements.txt (pinned — generated by pip-compile)
# pip install pip-tools
# pip-compile requirements.in
```

### Recommended pattern
```bash
# requirements.in — developer-maintained abstracts
# requirements.txt — pip-compile generated, commit this
# requirements-dev.txt — dev-only tools, also pinned

pip-compile requirements.in -o requirements.txt
pip-compile requirements-dev.in -o requirements-dev.txt

# Update all pins
pip-compile --upgrade requirements.in
```

## npm / Node Dependency Scanning

```bash
# Built-in audit
npm audit
npm audit --audit-level=high   # fail on high+

# Auto-fix (patch-level)
npm audit fix

# Snyk
npx snyk test
npx snyk monitor    # continuous monitoring

# Check for outdated packages
npm outdated

# Bundle analysis — catch unexpected large deps
npx webpack-bundle-analyzer stats.json
npx source-map-explorer build/static/js/*.js
```

### Lock file discipline
```bash
# ✅ Always commit lock files
git add package-lock.json    # or yarn.lock / pnpm-lock.yaml

# ✅ Use --frozen-lockfile in CI
npm ci                        # cleaner than npm install in CI
yarn install --frozen-lockfile

# ❌ Never delete and regenerate lock files casually — audit the diff
```

## Typosquatting Detection

Common typosquatting patterns to watch for:
- `reqeusts` instead of `requests`
- `fatsapi` instead of `fastapi`
- `djagno` instead of `django`
- Adding suffixes: `requests-pro`, `fastapi-extra`
- Lookalike names: `numpy-secure`, `pandas-utils`

```bash
# Before installing an unfamiliar package
pip show <package>                    # check maintainer, homepage
# Visit PyPI page — check download count, last update, maintainers

# Check if package name is close to a popular one
python -c "import Levenshtein; print(Levenshtein.distance('reqeusts', 'requests'))"

# GitHub: check stars, issues, recent commits before adding deps
```

## Dependabot / Renovate (Automated Dependency Updates)

```yaml
# .github/dependabot.yml
version: 2
updates:
  - package-ecosystem: "pip"
    directory: "/"
    schedule:
      interval: "weekly"
    open-pull-requests-limit: 5
    labels:
      - "dependencies"
      - "security"

  - package-ecosystem: "npm"
    directory: "/frontend"
    schedule:
      interval: "weekly"
    open-pull-requests-limit: 5
    ignore:
      - dependency-name: "*"
        update-types: ["version-update:semver-major"]  # manual review for majors
```

## SBOM — Software Bill of Materials

Generate an SBOM to track exactly what's in your production build:

```bash
# Python SBOM with cyclonedx
pip install cyclonedx-bom
cyclonedx-py environment -o sbom.xml

# With Syft (also works for Docker images)
syft packages myapp:latest -o cyclonedx-xml > sbom.xml
syft packages dir:. -o spdx-json > sbom.json

# Grype can scan an SBOM
grype sbom:sbom.xml
```

## Private Package Registries — Dependency Confusion

```bash
# ❌ Risk: attacker publishes public package with same name as your internal one
# pip/npm prefer higher version numbers — if attacker publishes v99 externally...

# ✅ Mitigation 1: Namespace internal packages (e.g., @mycompany/utils, mycompany-utils)
# ✅ Mitigation 2: Use --index-url to point only to your private registry
pip install --index-url https://your-registry.com/simple/ mycompany-utils

# ✅ Mitigation 3: pip.conf to set default registry
# ~/.pip/pip.conf or $VIRTUAL_ENV/pip.conf
# [global]
# index-url = https://your-private-registry/simple/
# extra-index-url = https://pypi.org/simple/

# ✅ Mitigation 4: Reserve your package names on PyPI even if not published
```

## GitHub Actions Supply Chain

```yaml
# ❌ Using mutable action references
- uses: actions/checkout@main           # moves — don't trust
- uses: some-org/some-action@v1         # tag can be rewritten

# ✅ Pin to full commit SHA
- uses: actions/checkout@11bd71901bbe5b1630ceea73d27597364c9af683  # v4.2.2

# ✅ Verify third-party actions
# 1. Read the action's source code before using
# 2. Prefer verified/official actions
# 3. Use few third-party actions — each one is a supply chain risk
```

## CI Security Scanning Pipeline

```yaml
# .github/workflows/security.yml
name: Security Scan
on: [push, pull_request]

jobs:
  python-audit:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.12" }
      - run: pip install pip-audit bandit semgrep
      - run: pip-audit -r requirements.txt --strict
      - run: bandit -r app/ -ll -ii
      - run: semgrep --config=auto --error app/

  npm-audit:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: "20" }
      - run: npm ci
      - run: npm audit --audit-level=high

  docker-scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Build image
        run: docker build -t myapp:${{ github.sha }} .
      - name: Scan with Trivy
        uses: aquasecurity/trivy-action@master
        with:
          image-ref: myapp:${{ github.sha }}
          exit-code: "1"
          severity: CRITICAL,HIGH

  secret-scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }
      - uses: trufflesecurity/trufflehog@main
        with:
          path: ./
          base: ${{ github.event.repository.default_branch }}
          head: HEAD
```

## Dependency Security Checklist

- [ ] `pip-audit` or `safety` in CI pipeline
- [ ] `npm audit` in CI pipeline
- [ ] Dependencies pinned (requirements.txt / package-lock.json committed)
- [ ] Dependabot or Renovate configured for weekly updates
- [ ] No packages with known CVEs (check NVD / OSV)
- [ ] No abandoned packages (last commit >2 years, no maintainer)
- [ ] Internal packages namespaced to prevent dependency confusion
- [ ] GitHub Actions pinned to SHA, not floating tags
- [ ] Secret scanning (trufflehog / gitleaks) in CI
- [ ] SBOM generated for production builds
