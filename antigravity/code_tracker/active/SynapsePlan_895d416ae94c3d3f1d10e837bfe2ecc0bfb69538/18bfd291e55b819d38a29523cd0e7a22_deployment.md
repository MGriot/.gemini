## Overview
This document outlines a general strategy for deploying SynapsePlan to a production environment. The recommended approach involves containerization with Docker and orchestration using `docker-compose` for simplicity, or Kubernetes for scalability.

## 1. Prerequisites
*   A cloud provider account (e.g., AWS, GCP, Azure) or a server with Docker and Docker Compose installed.
*   A PostgreSQL database instance (managed service recommended for production).
*   Domain name configured with appropriate DNS records.
*   SSL/TLS certificates for secure communication (e.g., Let's Encrypt).

## 2. Containerization (Already covered by `Dockerfile.backend` and `Dockerfile.frontend`)
*   Ensure `Dockerfile.backend` and `Dockerfile.frontend` are optimized for production builds (e.g., multi-stage builds, smaller base images).

## 3. Database Setup
*   **Managed PostgreSQL Service:** It is highly recommended to use a managed database service from your cloud provider (e.g., AWS RDS, Azure Database for PostgreSQL, Google Cloud SQL).
*   **Database Migrations:** Apply Alembic migrations to the production database:
    ```bash
    # Connect to your backend container (or run directly on the host with correct env)
    docker-compose exec backend alembic upgrade head
    ```

## 4. Environment Variables
*   **Backend:**
    *   `DATABASE_URL`: Connection string for your production PostgreSQL instance.
    *   `SECRET_KEY`: A strong, unique secret key for JWT. **DO NOT use the default from development.**
    *   `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`: Production SMTP server details.
*   **Frontend:**
    *   `VITE_API_BASE_URL`: The public URL of your backend API (e.g., `https://api.yourdomain.com`).
*   **Secure Management:** Use your cloud provider's secret management service (e.g., AWS Secrets Manager, Azure Key Vault, Google Secret Manager) or environment variables for Docker deployments.

## 5. Reverse Proxy & SSL (Nginx/Caddy)
*   **Nginx Configuration:**
    *   Configure Nginx as a reverse proxy to:
        *   Serve the static frontend files.
        *   Proxy requests to the backend FastAPI application.
        *   Handle SSL termination (HTTPS).
    *   Example Nginx configuration is provided in `nginx.conf`. Adjust as necessary for your domain and environment.

## 6. Deployment Options

### Option A: Docker Compose (for smaller scale or simpler deployments)
1.  **Build Images:**
    ```bash
    docker-compose build
    ```
2.  **Run Containers:**
    ```bash
    docker-compose up -d
    ```
3.  **Ensure Nginx Configuration:** Update `nginx.conf` (or similar) to point to the correct service names/ports if not using `docker-compose` for Nginx.

### Option B: Kubernetes (for scalable and resilient deployments)
1.  **Container Registry:** Push your Docker images to a container registry (e.g., Docker Hub, AWS ECR, GCP Container Registry).
2.  **Kubernetes Manifests:** Create Kubernetes YAML manifests for:
    *   Deployments (backend, frontend, Nginx).
    *   Services (LoadBalancer/NodePort for external access).
    *   Ingress (for routing external traffic and SSL).
    *   Secrets (for environment variables).
    *   Persistent Volumes (for PostgreSQL data if not using managed service).
3.  **Deployment:** Apply manifests to your Kubernetes cluster.

## 7. CI/CD Pipeline (Future Enhancement)
*   Automate testing, building, and deployment using tools like GitHub Actions, GitLab CI, Jenkins, etc.

## 8. Logging & Monitoring (Future Enhancement)
*   Integrate structured logging (e.g., `loguru` for backend).
*   Set up monitoring tools (e.g., Prometheus/Grafana, Sentry) for application performance and error tracking.

## 9. Security
*   Regularly update dependencies.
*   Implement web application firewall (WAF).
*   Regular security audits.
